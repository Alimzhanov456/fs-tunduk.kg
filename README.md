# Document Verify — свой сервис проверки документов по QR

Маленький Flask-сайт с двумя независимыми режимами (оба в разделах админки,
переключаются вверху страницы):

- **«Мои PDF»** — самое простое: загружаете готовый PDF-файл целиком, сайт
  сохраняет его и выдаёт QR. При сканировании открывается сам этот PDF
  (`/f/<ID>`), прямо на вашем домене — ничего кроме файла.
- **«Записи»** — вариант с базой данных: вы вводите поля документа (ФИО,
  дата и т.п.), сайт хранит их как запись и показывает на отдельной
  странице `/verify/<ID>`; тот же раздел умеет впечатать QR в уже готовый
  PDF-шаблон (а не просто отдать файл как есть).

Если нужно просто «залил PDF → получил QR → по QR открывается этот PDF на
моём домене» — используйте «Мои PDF», это самый короткий путь.

**Перед тем как класть сюда чьи-то настоящие персональные данные** — не
делайте этого. Это учебный проект без серьёзной защиты (нет rate-limit на
логин, нет аудита действий, простая парольная админка). Для реальных
документов людей это не готово.

## 1. Запуск локально

**Windows / PowerShell:**
```powershell
cd verify-site
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

$env:ADMIN_PASSWORD = "mypassword123"
$env:SECRET_KEY = "любая-длинная-случайная-строка"

python app.py
```

**Mac / Linux:**
```bash
cd verify-site
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

export ADMIN_PASSWORD=mypassword123
export SECRET_KEY=$(python -c "import secrets; print(secrets.token_hex(32))")

python app.py
```

Откройте http://localhost:5000/admin, войдите паролем из `ADMIN_PASSWORD`
(если переменную не задали — пароль по умолчанию `change-me`, он прописан в
`app.py`). Создайте документ — получите QR и сможете сразу впечатать его в
свой PDF.

### 1a. Проверить, что QR реально открывается как сайт — прямо сейчас, без деплоя

QR, сгенерированный локально через `http://localhost:5000/...`, откроется
только на этом же компьютере — телефон снаружи его не увидит, это не баг, а
следствие того, что сайт пока нигде не выложен. Чтобы прямо сейчас
отсканировать QR телефоном и увидеть, как открывается сайт (до всякого
деплоя и домена):

1. Телефон должен быть в той же Wi-Fi сети, что и компьютер.
2. Узнайте локальный IP компьютера:
   - Windows: `ipconfig` → строка "IPv4-адрес" (обычно `192.168.х.х`)
   - Mac: `ipconfig getifaddr en0`
3. На **компьютере** откройте не `localhost:5000/admin`, а
   `http://<ваш-IP>:5000/admin` (например `http://192.168.1.42:5000/admin`)
   — важно зайти именно так, тогда сайт узнает этот адрес и впишет его в QR.
4. Создайте документ — QR теперь будет вести на `http://<ваш-IP>:5000/verify/...`.
5. Сканируйте этот QR телефоном (той же Wi-Fi) — откроется страница
   проверки прямо в браузере телефона.

Если телефон не подключается — скорее всего брандмауэр Windows блокирует
входящие соединения на порт 5000; разрешите его для `python.exe`, или
временно отключите брандмауэр для теста.

Это только для проверки механики у себя дома. Чтобы QR работал у кого
угодно и постоянно, а не только у вас в Wi-Fi — нужен шаг 3 (деплой) и
шаг 4 (домен) ниже: тогда сайт сам подставит в QR уже настоящий домен,
менять код не придётся.

### 1b. Самый короткий путь: загрузил PDF → получил QR → QR открывает этот PDF

Если не нужны никакие поля/данные, а нужно просто "мой PDF открывается по
QR" — идите в раздел **«Мои PDF»** (ссылка вверху страницы после входа в
админку):

1. `/admin/pdfs` → выберите свой PDF-файл → «Загрузить и получить QR».
2. Сайт покажет QR и ссылку вида `.../f/AB12CD34`.
3. Сканируете QR (см. 1a про локальный тест по Wi-Fi, или уже настоящий
   домен после деплоя) — открывается ровно этот PDF, как обычная ссылка на
   файл.

Ничего впечатывать в сам PDF не обязательно — можно просто держать QR
рядом с бумажной версией документа или напечатать его отдельным стикером.
Если хочется, чтобы QR был физически встроен в сам файл — скачайте PNG с
QR (кнопка на странице документа) и вставьте картинку в PDF любым
редактором (Word, Canva, Acrobat и т.п.), либо через `stamp_qr_cli.py` из
командной строки: `python stamp_qr_cli.py моя.pdf "<ссылка с этой страницы>" итог.pdf`.

## 2. Данные (чтобы документы не терялись)

По умолчанию сайт пишет в локальный файл `local.db` (SQLite) — годится
только для локальных тестов. У большинства бесплатных хостингов диск
"эфемерный": при каждом передеплое (не при каждом добавлении документа —
именно при обновлении кода) файл может стираться.

Раз вам нужно **добавлять документы самостоятельно, без передеплоя** — это
как раз не проблема: SQLite прекрасно переживает обычную работу сайта между
деплоями. Проблема только в том, что при следующем обновлении кода данные
могут исчезнуть. Два варианта:

- **Простой:** пока не планируете часто обновлять код — оставьте SQLite как
  есть, но периодически скачивайте `local.db` себе как бэкап.
- **Надёжный:** подключите бесплатную облачную Postgres — она живёт отдельно
  от хостинга сайта и не зависит от передеплоев. Например
  [neon.tech](https://neon.tech) (есть бесплатный план): создайте проект,
  скопируйте `DATABASE_URL` (вида `postgresql://user:pass@host/db`) и
  задайте его переменной окружения `DATABASE_URL` на хостинге — код уже
  умеет её подхватывать, ничего в `app.py` менять не нужно. Драйвер для
  Postgres не входит в основной `requirements.txt` (чтобы не мешать
  локальной установке) — поставьте его отдельно, когда дойдёте до этого
  шага: `pip install -r requirements-postgres.txt`. Если на вашей версии
  Python/Windows он не соберётся — в этом файле есть готовая альтернатива.

## 3. Деплой на хостинг

Любой хостинг, который умеет Python/Flask-приложения, подойдёт. Самый
простой бесплатный вариант — **Render.com**:

1. Зарегистрируйтесь на render.com, подключите GitHub (залейте эту папку в
   свой репозиторий) — или воспользуйтесь Render's "Deploy from a Git repo".
2. New → Web Service → выберите репозиторий.
3. Build command: `pip install -r requirements.txt`
   Start command: `gunicorn app:app`
4. В Environment добавьте переменные:
   - `ADMIN_PASSWORD` — свой пароль
   - `SECRET_KEY` — случайная строка (см. команду выше)
   - `DATABASE_URL` — если подключили Neon/Supabase (шаг 2)
5. Deploy. Через пару минут сайт будет на `https://ваш-проект.onrender.com`.

Альтернатива с сохранением файлов на диске между деплоями — **Railway.app**
(есть Volumes для персистентного хранилища) или обычный VPS
(DigitalOcean, Timeweb, Beget и т.п.), если хочется полного контроля.

## 4. Свой домен

Домен и хостинг — это две разные вещи, соединяются через DNS:

1. Купите домен у любого регистратора (Namecheap, REG.RU, Cloudflare
   Registrar, nic.kg для `.kg`, и т.д.).
2. На хостинге (Render → ваш сервис → Settings → Custom Domain) добавьте
   свой домен — сервис покажет, какую DNS-запись нужно создать (обычно
   `CNAME` на что-то вроде `ваш-проект.onrender.com`, или `A`-запись с IP).
3. Зайдите в панель регистратора (или переключитесь на Cloudflare DNS —
   бесплатно и удобно) и добавьте именно ту запись, которую показал
   хостинг.
4. Подождите от нескольких минут до пары часов (обновление DNS). Render сам
   выпустит бесплатный HTTPS-сертификат (Let's Encrypt) на ваш домен.

После этого `/verify/<ID>` будет открываться как
`https://ваш-домен.tld/verify/AB12CD34` — и именно такую ссылку сайт сам
закодирует в QR при выпуске документа (код берёт адрес из того, с какого
домена его открыли, ничего вручную прописывать не нужно).

## 5. Как это использовать под задание

1. `/admin` → заполните форму (название документа, владелец, любые
   дополнительные поля, какие требует ваше задание) → получите ID и QR.
2. На той же странице документа загрузите PDF-шаблон вашего документа →
   сервер впечатает QR в нужное место страницы → скачайте готовый PDF.
3. Отсканируйте QR — попадёте на `/verify/<ID>` на своём домене, увидите
   ровно те данные, что ввели.
4. Показываете преподавателю: PDF с QR + сайт на своём домене + объяснение
   архитектуры (см. `app.py` — там расписан весь поток в комментарии
   наверху файла).

`stamp_qr_cli.py` — тот же механизм впечатывания QR, но из командной
строки, без запуска сайта, если хочется быстро проверить, как QR ляжет на
макет конкретного PDF.
